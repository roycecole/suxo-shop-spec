# 更新缺口分析 (10-gap-analysis.md)

`docs/10-gap-analysis.md` 是**活文件**，不是像異動紀錄一樣的附加式紀錄——內容會隨缺口被解決或新缺口浮現而**原地重新編輯/重組**。

## 標記一個缺口已解決

1. 找到該缺口所在的表格列（通常在 §1 技術面 / §2 流程商業面 / §3 維運面 / §5 設計面 / §6 ShyeCMS 專案面 / §7 多語系連鎖影響 / §8 資安面 / §9 Repo 拆分新缺口 之一）。
2. 項目名稱用 `~~刪除線~~` 包住，說明欄改寫成「**已解決**：<具體怎麼解決的>，見 [對應文件](連結)」——參考文件內既有的已解決列（如 `~~Correlation ID 貫穿追蹤~~` 那幾行）的既有寫法。
3. 不要把整列刪除——保留刪除線列讓人看得出「這裡曾經是個缺口，現在怎麼收斂的」。

## 新增一個新發現的缺口

1. 判斷屬於哪個既有分節（§1–§9）；如果都不適合，可以比照既有慣例新增一個新的 `## N. XXX面` 分節（注意：本文件過去每次新增分節時，`docs/30-open-decisions-register.md` 建議編號和「設計系統文件建議編號」等交叉引用都要跟著往後挪一位，逐一確認有沒有踩到既有引用）。
2. 用表格列新增（`| 項目 | 說明 |`），說明欄要交代「為什麼是缺口」「牽涉哪些既有決策/文件」。

## 完成後

1. 依 spec-add-changelog-entry 的步驟新增異動紀錄，具體寫出這輪分析新增/解決了哪些項目。
2. 若異動影響到 §4「建議下一步」的排序，一併檢查是否需要調整。
3. 用 spec-sync-open-decisions-register 確認 `30-open-decisions-register.md` 是否需要同步。
