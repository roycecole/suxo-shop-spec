# 新增異動紀錄 (Changelog Entry)

適用時機：對 `docs/` 底下任何一份 `.md` 文件做出**實質內容修改**時（新增章節、修改決策、調整資料模型等）。純粹修正錯字/格式不一定需要，但有疑慮時仍建議記錄。

## 步驟

1. 打開該文件最上方的「## 異動紀錄」表格（`版本` / `日期` / `作者` / `說明` 四欄，每份文件都有）。
2. 版本號規則：延續該文件既有的 `v0.x` 序號，新增一列 `v0.(x+1)`（不要跳號，也不要重用舊版號）。
3. 日期欄：使用當下日期（YYYY-MM-DD）。
4. 作者欄：延續該文件既有慣例（通常是 `ordinarycas`），除非使用者另有指示。
5. 說明欄：**回應「什麼需求/指示」做了「什麼修改」**——參考既有列的寫法，通常是「回應『原始需求原文』需求，新增/修正/移除...」。要具體到看得出動機，不要只寫「更新內容」。
6. **不要修改既有列**——異動紀錄是附加（append），舊列原封不動保留。
7. 新增列之後，再進行本次要做的實際內容修改。

## 常見連動

- 若這次修改影響到其他文件的索引或交叉引用（如新增一份服務文件、新增一個決策），記得同步更新（見 spec-check-cross-references、spec-sync-open-decisions-register）。
- 若修改的是待決議事項，改用 spec-resolve-open-item 的做法（劃刪除線+註記，不要直接刪除該行）。
