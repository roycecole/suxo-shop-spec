# 解決或新增待決議事項 (Open Item)

適用時機：某份文件末尾的「## 待決議事項」（格式為 `- [ ] ...`）清單裡，有一項因為使用者的新指示而被決定/解決了；或是需要新增一項待決議。

## 解決一個既有項目

1. 找到該項目所在的原始文件（**不是** `30-open-decisions-register.md`——那只是索引，見 spec-sync-open-decisions-register）。
2. **不要刪除該行**。改為：
   - 用 `~~刪除線~~` 包住原本的問題敘述。
   - 緊接著補一句「，**已解決**：<實際做了什麼決定，附上依據或連結>」或使用文件既有慣例的措辭（可參考 `10-gap-analysis.md` 裡 `~~Correlation ID 貫穿追蹤~~` 這類已解決項目的寫法：先劃刪除線的項目名，再接「**已解決**：具體結論＋連結」）。
3. 依 spec-add-changelog-entry 的步驟在該文件新增一筆異動紀錄，說明解決了哪個待決議事項。
4. 若這個項目也出現在 `30-open-decisions-register.md`，用 spec-sync-open-decisions-register 同步。

## 新增一個待決議項目

1. 加在該文件「## 待決議事項」章節最後一行，格式為 `- [ ] <具體問題敘述，包含為什麼懸而未決>`。
2. 敘述要具體到未來的人不需要回頭挖掘上下文就懂問題是什麼（參考既有項目的寫法，通常會點出「卡在哪個決策/依賴上」）。
3. 若這是一個橫跨多份文件、值得列入前 10 大優先處理的重大項目，額外提醒使用者是否要同步進 `30-open-decisions-register.md`。
