# 07 - 前台需求 (Storefront Requirements)

來源文件：`docs/07-storefront-requirements.md`

## 這份文件負責回答
前台核心原則是免登入即可下單；列出頁面清單並對應到負責的微服務，另有現貨顯示的降級行為考量。

## 涵蓋章節
- 1. 核心原則：免登入即可下單
- 2. 登入方式（可選，非必要）
- 3. 頁面清單與對應服務（含 3.1 首頁互動 3D 芭樂效果，見下方使用注意）
- 4. 商品詳情頁的現貨顯示
- 5. 待決議事項
- 6. RWD / PWA / 無障礙規範

## 使用注意
- **§3.1 是 2026-09-09（v0.8）新增的整節**：記錄 `ecommerce-storefront` 首頁已實作、先前只活在程式碼與元件註解裡的互動式 3D 芭樂模型（純 three.js 程序化建模`LatheGeometry`，不載入外部模型/貼圖檔；支援拖曳旋轉+慣性、點擊切開剖半、鍵盤操作與 `aria-pressed`、`prefers-reduced-motion` 降級）——這是把既有實作補回規格，不是新設計；查詢首頁需求時不要漏看。此效果在首頁模板裡寫死，不透過 CMS Service 管理，賣家無法關閉。
- §5 待決議事項僅剩 1 項開放（LINE/Google OAuth 實際串接時程，屬業主資源排程的業務決策，非技術判斷）。訪客結帳簡訊防詐項（v0.10）已定案**不強制簡訊驗證**，採速率限制＋Email 驗證的分層防詐；訪客升級會員機制也已定案（需信箱驗證通過）。不要誤以為 §5 還有技術面待解問題。
