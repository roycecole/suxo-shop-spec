# 10 - 缺口分析與建議調整 (Gap Analysis)

來源文件：`docs/10-gap-analysis.md`

## 這份文件負責回答
這是活文件（living document），會隨缺口解決或新缺口浮現而原地編輯，不是一次性快照。

## 涵蓋章節
- 1. 技術面
- 2. 流程/商業面
- 3. 維運面
- 4. 建議下一步（依風險排序）
- 5. 設計/前端面（新，因應動畫決策浮現）
- 6. ShyeCMS 專案面（因應「確認專案清單」浮現）
- 7. 多語系/圖表/Markdown 決策的連鎖影響
- 8. 資安面（因應「資訊安全性非常重要」正式收斂）
- 9. Repo 拆分（決策 H）帶來的新缺口

## 使用注意
- 編輯這份文件前先參考 spec-update-gap-analysis 這個 Skill 的操作步驟：解決的項目用 ~~刪除線~~ 標記並註明已解決方式，不要直接刪掉該行。

## 修改這份文件時
- 依 `spec-add-changelog-entry` Skill 的步驟新增異動紀錄（版號/日期/作者/說明），不要靜默修改內容。
- 若此文件的異動影響到其他文件的索引或交叉引用，依 `spec-check-cross-references` Skill 檢查並同步。
