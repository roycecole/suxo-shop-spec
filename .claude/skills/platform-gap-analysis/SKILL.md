# 10 - 缺口分析與建議調整 (Gap Analysis)

## 這份文件負責回答
這是活文件（living document），會隨缺口解決或新缺口浮現而原地編輯，不是一次性快照。

## 涵蓋章節
- 1. 技術面
- 2. 流程/商業面
- 3. 維運面
- 4. 建議下一步（依風險排序）
- 5. 設計/前端面（新，因應動畫決策浮現；設計系統 Token 仍是本文件少數真正還開放的缺口）
- 6. ShyeCMS 專案面（因應「確認專案清單」浮現）
- 7. 多語系/圖表/Markdown 決策的連鎖影響
- 8. 資安面（因應「資訊安全性非常重要」正式收斂）
- 9. Repo 拆分（決策 H）帶來的新缺口
- 10. 微服務 API/資料模型缺漏（第七輪跨文件複查）
- 11. 跨文件一致性與決策矛盾（第七輪跨文件複查）
- 12. 前後台需求規格落差（第七輪跨文件複查）
- 13. 文件互相引用但承諾未兌現（第八輪複查）
- 14. 本輪新增設計（會員登入、Saga 補償）帶來的連鎖影響（第九輪複查）

**現況（2026-09-10）**：§1–4、6、8、9、14 列出的項目已逐一核對並標記解決（詳見異動紀錄 v0.20），
§10–13 更早的複查也已全數處理完畢（各自小結已寫「本節 N 項已全數處理完畢」）。真正還開放的缺口
